# Documentación pública (`docs/public`)

Esta sección está pensada para **todo el mundo**: visitantes del repositorio en GitHub, revisores, jueces de hackathon y futuros colaboradores. Todo lo que pongas aquí se asume **aportable y revisable en abierto**.

## Para qué sirve

- Explicar el producto o el demo de forma clara sin abrir el código.
- Dejar decisiones técnicas o de producto que quieras mostrar públicamente.
- Añadir material de “pitch” o README extendido (arquitectura, diagramas, guía de usuario corta).
- Complementar el `README.md` raíz con profundidad donde tenga sentido.

## Convenciones sugeridas

- Usa nombres de archivo descriptivos (`arquitectura.md`, `demo-checklist.md`).
- Evita duplicar secretos: placeholders del estilo `TODO_RPC_URL` si necesitas ejemplos.
- Si enlazas a despliegues o explorers, prefiere URLs públicas conocidas (devnet/testnet) y no credenciales.

## Relación con otras carpetas

- La documentación **interna** del equipo vive en `docs/internal/` y **no** forma parte del historial de Git (solo existe en discos locales del equipo). Esta carpeta `public/` es el sitio correcto para todo lo que sí quieras que viaje con el repo.
